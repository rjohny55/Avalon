# SM80 chunked GDN prefill — CMP170HX

Measured on 2026-11-05 with one NVIDIA CMP170HX (SM80, 70 SMs, 64 GB), CUDA 12.9. Same Avalon binary, weights, input token arrays and sampling settings; the backend was selected through environment flags. Three cold-KV and three warm-KV requests per input length, sequentially. Values below are medians. The model stayed loaded; cold KV does not mean cold expert caches. No concurrent inference or package installation during the full-model comparison.

Model: `freriadoc/Qwen3.8-Flash-Next-Avalon-GGUF`, IQ3KS, 33 main shards, plus `mtp-Qwen3.8-Flash-Next-shared-IQ3K-IQ4NL-FR65k.gguf`. The 35 downloaded files were fully rehashed. One GPU, 262144 context, batch/ubatch 4096, parallel 1, CPU threads 24, Flash Attention and CUDA Graphs enabled, K q8_0 / V q4_0, MTP draft maximum 2. Sampling: temperature 0.7, top-p 0.8, top-k 20, min-p 0, presence penalty 1.5, repeat penalty 1, seed 42, thinking disabled, 128 final output tokens.

## Full-model results

| Input tokens | Baseline prefill, tok/s | Chunked prefill, tok/s | Throughput gain | Baseline TTFT, s | Chunked TTFT, s | TTFT reduction |
|---:|---:|---:|---:|---:|---:|---:|
| 8192 | 1208.29 | 1282.35 | 6.13% | 7.127 | 6.750 | 5.28% |
| 32768 | 1173.50 | 1243.87 | 6.00% | 27.945 | 26.366 | 5.65% |

TTFT is wall time from HTTP submission to the first nonempty text chunk. Prefill throughput comes from server timings. These are different measurements and include different overheads. Peak VRAM was approximately 59958 MiB with chunked prefill versus 59960 MiB in the baseline; this difference is noise.

Warm decode medians were 82.73 -> 83.20 tok/s at 8K and 79.12 -> 82.29 at 32K, with substantial run-to-run variation. This change targets prefill; these samples do not establish a decode gain. A separate grouped-keyhead decode experiment improved selected operator timings but reduced full-model warm decode medians to 79.27 and 76.94 tok/s. That experiment is not included in the release or the optimization PR.

The chunked operator is about 5.9x faster here. This is a microbenchmark, not a whole-model speedup. These earlier operator runs were not part of the later quiet full-model measurement window.

## Correctness and limits

The research comparison passed 103 CPU-reference cases in each of four backend modes (412 case executions), including output, committed state and replay stash checks, nonzero initial states, weak decay, odd chunk lengths, strided tensors, cache fusion and gathered state. Existing tolerances were unchanged. Both chunked variants passed three generated-code checks (interval merge, LRU cache and Dijkstra) at roughly 26K input tokens; generated code was parsed and executed against independent assertions. This small sample is not a broad quality evaluation and does not prove bitwise equivalence.

The optimized path uses FP16 scaled high/residual tensor-core products with FP32 state. It is opt-in upstream through `GGML_CUDA_GDN_SM80_CHUNKED=1`. The release launcher enables it by default; set the variable to `0` to disable it. Dispatch requires exact SM80, adequate SM/shared-memory capacity, D=128, Hk=16, Hv=48, a single sequence, aligned supported tensors and at least 128 tokens. Other hardware and unsupported shapes keep the existing path. No decode kernel is replaced.

The long-context launch fix is separate: https://github.com/freriadoc/Avalon/pull/30. The release includes it; the prefill PR does not duplicate it. A 64K-input smoke test with the research candidate completed without CUDA errors or interrupted output; it is not an additional three-run performance result.

## Reproduce

Build with CUDA SM80 support. Compare identical inputs with the following variable unset/`0` and then `1`, using a new server process for each mode:

```sh
GGML_CUDA_GDN_SM80_CHUNKED=1 ./llama-server ...
GGML_CUDA_GDN_SM80_CHUNKED=1 ./test-backend-ops test -o GATED_DELTA_NET
GGML_CUDA_GDN_SM80_CHUNKED=1 ./test-backend-ops perf -o GATED_DELTA_NET
```

Record raw timings, actual reused KV tokens and final output token counts. Do not count speculative draft tokens as final decode throughput. Test only one model instance at a time on this card. Results apply to this model, card and configuration; other workloads require measurement.
